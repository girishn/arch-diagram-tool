# Backlog

Re-prioritised 2026-10-29 after a research pass (seven angles: landscape, accessibility, rendering performance, layout, spec design, generators, packaging and icons). The report and its notes are not part of this repository. Item numbers in brackets, like (#5), are its list numbers.

How to read it:

- **Effort:** S under a day, M one to three days, L more than three. These are judgement, not measurements.
- **Evidence:** P = a primary source (a standard or official documentation), S = secondary (blogs, vendor pages, forums), I = the researchers' or my inference. Anything marked I is a hypothesis to test, not a finding.
- **Status** lines say what the repo already has, because the report was written without reading the code.

The report's own conclusion drives the order: close the accessibility, testing and Safari-trust gaps in what exists, then make the spec a contract, then build generators, with a Terraform drift check ahead of any LLM feature. Tier 1 is chosen to be worth doing whatever else turns out.

- **P3c. View-switch glitch (icons cut off or missing while changing to the top view): DONE 2026-10-30 (UX bug).** Reported by the owner. Cause, confirmed by capturing real frames during the switch: the diagram has no perspective, so depth is decided only by the 3D sort, and while the plane turned over 0.9 s its pedestals were drawn in front of the upright cards. For most of the rotation the cards were hidden (a sliver of an icon at best, no labels), and they popped into place at the end. It happened in Chromium when switching to the top view; WebKit and the switch back to isometric were already fine. Fix: each card's anchor is pushed 200 px towards the viewer along its own axis (`translateZ`). With no perspective that changes nothing on screen, it only wins the depth sort. Checked by contact sheets of frames in Chromium (both directions) and WebKit. Regression test: the browser tests pause the running transitions at 150, 400 and 700 ms, screenshot the API icon and count how much of it is its purple, in both directions and both browsers; with the fix switched off the three Chromium cases for the top view fail. Two earlier ideas were tried and dropped: delaying the card's own shift (it made the cards hidden for the whole turn, because the cards were behind the pedestals from the start), and a pixel hit-test probe (it reported nothing covered while the screen showed otherwise, since hit-testing in 3D does not match what is drawn). Not done: the same depth bias is applied to the arrow labels because they share the anchor transform, which is intended but not separately tested.

## Not recommended

Researched and rejected. Reopen only with new evidence.

- **Bundling or committing vendor icon sets (AWS, Azure, others).** No source permits bundling in an open-source package; AWS's redistribution terms were never read (V1). Generic shapes by default and user-supplied packs.
- **Rewriting the renderer in Canvas, WebGL or three.js.** Measured degradation starts above about 400 nodes against a target of 5 to 40; a three.js version was already rejected.
- **Live cloud-account import, collaboration and comments.** SaaS strengths (Cloudcraft, Hava, IcePanel), out of scope for a solo static-export library.
- **A custom DSL.** LikeC4 and Structurizr own that space. Keep JSON with a schema and add exporters.
- **Structurizr JSON or ArchiMate as the native format.** Storage and transport formats, not authoring ones. Export targets only.
- **Shipping ELK, libavoid WASM or any layout engine in the browser bundle.** Size, a served `.wasm` and async init, and non-deterministic layout. Run layout offline and commit positions.
- **Shipping Zod, Ajv or Valibot at runtime just for validation.** Keep the dependency-free validator; use a schema generator at build time.
- **`role="application"` on the viewport.** It removes screen-reader browse mode.
- **In-browser DOM-to-image capture of the 3D view,** and GIF or MP4 trace export for now (the most expensive item with the least evidence).
- **A hosted free-form `generate_diagram(prompt)` service,** and making Pluralith or Inframap dependencies (Pluralith is alpha and account-bound; Inframap models no IAM).
- **Splitting into multiple views and a full model/view file layout yet.** Defer until a second real use case exists.
- **Decided earlier:** a validator warning for `labelAt` inside a node's footprint (the renderer handles it), and drawing a node once per AZ or region (use the Reliability lens text).

### Kubernetes and large systems

Parked 2026-10-29 at Girish's request, for later versions. See L7.

A huge cluster cannot be drawn literally: layout is manual, and the CSS-3D renderer is probably readable only up to roughly 30–40 nodes per diagram (an estimate, untested). Plan when this is picked up:

- **Drill-down.** One diagram per level (cluster, namespace, workload group). Add an optional `expands` on a node pointing at a child spec.
- **Generator.** Collapse Kubernetes objects into logical nodes, grouped by `app.kubernetes.io/part-of` or similar. Deployment + ReplicaSet + Pods + HPA become one node with `scale`. A Service becomes the link `protocol`. Ingress or Gateway becomes a node. ConfigMap, Secret and ServiceAccount are omitted unless they matter. This belongs to the generator stage, alongside Terraform to spec.
- **Zone kind.** Maybe add `namespace` to `ZONE_KINDS`; until then use `group`.
- **First step when resuming.** Hand-write a small example (three services in a namespace with an Ingress, an HPA and a CronJob) to test the mapping before building anything.

Mapping sketch: cluster and namespace are zones; Deployment, StatefulSet and DaemonSet are nodes; HPA is `scale`; Job and CronJob are nodes with `batch` or `event` links; PVC is a storage node with a `dependency` link; NetworkPolicy and RBAC are the Security lens and `boundary` zones.

### Readable text size

Found while fixing target sizes: the diagram is scaled to fit its frame, commonly to about 0.7x, so a 14 px name plate and 10 px arrow label are drawn at roughly 10 px and 7 px. WCAG sets no minimum text size, but this makes labels hard to read until the visitor zooms. Options to weigh: a larger base size for labels, a floor on the fit scale with panning instead of shrinking, scaling text less than the plane, or a "large labels" setting. Needs a decision on whether the whole diagram must be visible at first load. Interacts with spacing (bigger labels need wider gaps) and with P3b.

## Spacing follow-ups

- Chip and plate widths are estimates from character counts. A lens badge that is longer than the link's label can still cover more cable than planned.
- Only straight, side-by-side cables get extra room. A cable that runs diagonally, or is routed with `via`, can still be shorter than its chip.
- Spacing widens per gap, so one long label stretches that gap for every row. A diagram with a few very long labels gets wide.

### Zoom and pan follow-ups

- Wheel and pinch zoom shipped (towards the pointer, 0.6x to 3x). Pinch was tested with synthetic pointer events, and the trackpad pinch relies on browsers sending it as a Ctrl+wheel event; neither is tested on real hardware (V2, skipped).
- A diagram narrower than its frame stays centred while zooming, so zoom-to-pointer only shows its full effect once the content overflows the frame.
- A plain wheel is deliberately left to scroll the page. A host that wants it to zoom could opt in with a prop.
- Touch: one finger pans in both views and two fingers twisting rotate the isometric view (added 2026-11-01, untested on a real device). Touch pan is wired (`touch-action: none` once zoomed) but untested on a real device (V2, skipped; Chrome DevTools touch emulation can cover the events).
- Drag pans in both views; shift-drag and right-drag rotate the isometric view (tested in `drag.spec.ts`). The two-finger twist is not tested.

### Theme follow-ups

The theme selector shipped (five built-in themes, a `theme` prop, an optional toolbar picker, `npm run check-themes`). Still open:

- Fonts are bundled with each theme. A separate font pairing control (serif, sans, mono) independent of colour is not built.
- Follow `prefers-color-scheme` for the default theme, and a light variant for each dark theme.
- Zone-kind colours (VPC blue, subnet green, cluster purple and so on) are fixed mid-tones, not per-theme, and are not in the contrast check (extend it as part of P5).
- The contrast check does not cover the zone tints, the dashed outlines of peripherals, or the chip backgrounds (P5).
- Name-plate size is one token (`--adg-name-size`, default 14px); decide whether sizes belong to a theme or a separate density setting.
- Persisting the choice is the host's job today. A small helper (read and write a storage key safely) could ship with the package.

### Zone label follow-ups

Labels are placed by search (bottom edge, top edge, then just outside the zone) so they clear cards, cables, arrow chips and other zones' labels and edges; nested zones keep 38 px between their edges so a parent's label fits. Still open:

- One label of the 29 across the four examples in both orientations has no clear spot: the scaling-group label in `platform-tooling` in the portrait layout. `ZoneRect.isLabelClear` reports it, and the label falls back to the least-bad position.
- Label width is estimated from the character count (about 7.4 px each). A real text measurement would be exact, but needs the DOM, which the pure layout module avoids.
- Placement is computed for the top view. In the isometric view the cards stand up off the plane, so a label can still sit behind a card there.
- A label hung outside its zone can read as detached; a small tab or leader line would tie it back.

### Peripherals follow-ups

- Toggling Tooling now re-lays out the diagram, so core nodes can jump to new positions instead of staying put. An animated transition between the two layouts would soften that.
- Logs or traces shipped out (`stream`) are documented but have no example yet; add a log store node to `examples/platform-tooling.json` when a layout slot is free.

## Where the evidence is thin

Taken from the report, so the order above is not mistaken for certainty:

- No source says CSS 3D transforms break focus visibility or WCAG 2.4.11; it needs testing (V3).
- ELK performance at 10 to 100 nodes was never measured, and there is no independent elkjs-versus-dagre benchmark.
- Bundle sizes of Ajv, Zod and Valibot were not sourced reliably; measure before choosing.
- Terraform specifics (`depends_on` representation, `terraform providers schema -json`, last-commit dates for Inframap, Rover, Pluralith and TerraVision, and TerraVision's licence history) are unverified.
- Competitor claims (LikeC4's dynamic views and MCP, FossFLOW, Hava, Brainboard, Lucidscale, Backstage plugins, Mermaid's ELK default) are unchecked.
- All effort estimates and performance budgets are judgement.
